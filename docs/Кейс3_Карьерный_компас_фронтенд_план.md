## 1. Описание продукта и бизнес-логика

### Концепция

«Карьерный компас» — это веб-приложение, которое помогает студенту без опыта в IT определиться с профессией и получить конкретный план действий на 12 месяцев.

### Пользовательский путь на фронтенде

```
Главная → Опросник (8–10 вопросов) → Результаты (топ-3 профессии)
         → Выбор профессии → Дорожная карта с прогрессом
```

### Ключевые страницы / экраны

| Экран | Что пользователь видит |
|-------|----------------------|
| **Главная (Landing)** | Приветствие, кнопка «Начать опрос», краткое описание — «3 шага к твоей IT-профессии» |
| **Опросник** | Один вопрос за раз с вариантами ответов; прогресс-бар (вопрос X из Y); кнопки «Назад» / «Далее» |
| **Результаты** | Топ-3 профессии с карточками: название, процент совпадения, пояснение «почему это ты»; кнопка «Выбрать →» |
| **Экран выбора** | После клика — подтверждение выбора |
| **Дорожная карта** | Список этапов (stage → steps), шаги можно отмечать как пройденные, прогресс-бар для каждого этапа и общий |
| **Профиль / Прогресс** | (Опционально) Сводка по всем шагам, сколько осталось |

## 3. Функциональные требования к фронтенду

### Лендинг
- Hero-секция с заголовком, подзаголовком, CTA-кнопкой «Начать опрос»
- Три шага в картинках/иконках: 1. Ответь на вопросы → 2. Получи рекомендацию → 3. Следуй плану
- Футер с контактами (или просто копирайт)

### Опросник
- 1 вопрос на экране (для фокуса пользователя)
- Прогресс-бар «Вопрос 3 из 10»
- Типы вопросов: radio (один вариант), checkbox (несколько), scale (1–5) — опционально
- Кнопка «Далее» (активна только когда выбран ответ)
- Анимация перехода между вопросами (опционально — fade/slide)
- После последнего вопроса — кнопка «Получить результат»

### Результаты (рекомендации)
- 3 карточки профессий, отсортированные по убыванию рейтинга
- На каждой карточке: название, «совпадение XX%», иконка/эмодзи, краткое пояснение
- Карточки кликабельны — при выборе открывается дорожная карта
- Анимация появления карточек (stagger)

### Дорожная карта
- Этапы (stage) как аккордеон или секции
- Внутри каждого этапа — список шагов
- Каждый шаг: название, тип (теория/практика/хакатон), ссылки на ресурсы, часы
- Чекбокс «Пройдено» для каждого шага
- Прогресс-бар для каждого этапа + общий прогресс сверху страницы
- Рекомендация следующего шага (выделенный блок)

### Loading / Error / Empty States
- **Loading:** скелетоны / спиннер при загрузке данных
- **Error:** сообщение об ошибке с кнопкой «Попробовать снова»
- **Empty:** если нет данных — соответствующее сообщение (например, «Вы ещё не прошли опрос»)

## 5. Маршрутизация (React Router)

```
/                    → LandingPage      (Главная)
/quiz                → QuizPage         (Опросник)
/results             → ResultsPage      (Результаты)
/roadmap             → RoadmapPage      (Дорожная карта)
/roadmap/:profession → RoadmapPage      (Карта конкретной профессии)
*                    → NotFoundPage      (404)
```

**Как передаём session_id:**
- При старте опроса бэкенд возвращает `session_id`
- Сохраняем в `sessionStorage` (до закрытия вкладки / браузера)
- При перезагрузке проверяем `sessionStorage` и продолжаем опрос
- После завершения — `session_id` остаётся для загрузки прогресса

## 7. Стейт-менеджмент и типы данных

### React Context

```typescript
// quizContext.tsx — состояние опросника
interface QuizState {
  sessionId: string | null;
  currentQuestion: Question | null;
  questionIndex: number;
  totalQuestions: number;
  answers: Record<number, number[]>; // question_id → [option_ids]
  isFinished: boolean;
  recommendations: Recommendation[] | null;
  selectedProfession: string | null;
}
```

### Типы данных (TypeScript)

```typescript
// types/api.ts — полное отражение API бэкенда

interface Question {
  question_id: number;
  question_text: string;
  question_type: 'single_choice' | 'multiple_choice' | 'scale';
  options: AnswerOption[];
}

interface AnswerOption {
  option_id: number;
  text: string;
}

interface Recommendation {
  profession_id: string;
  profession_name: string;
  score: number;
  reason: string;
  market_demand: number;
}

interface Roadmap {
  profession_id: string;
  profession_name: string;
  stages: Stage[];
}

interface Stage {
  stage_id: number;
  title: string;
  description: string;
  steps: Step[];
  progress?: number; // заполняется после загрузки прогресса
}

interface Step {
  step_id: number;
  title: string;
  step_type: 'theory' | 'practice' | 'milestone' | 'hackathon' | 'job_search';
  resources: Resource[];
  estimated_hours: number;
  completed?: boolean;
}

interface Resource {
  title: string;
  url: string;
}

interface Progress {
  overall_progress: number;
  stages_progress: StageProgress[];
  next_step: Step | null;
}

interface StageProgress {
  stage_id: number;
  title: string;
  progress: number;
  steps_total: number;
  steps_done: number;
}
```

## 8. Интеграция с API бэкенда

### Базовый URL

```typescript
const API_BASE = import.meta.env.VITE_API_URL || 'http://localhost:8000/api/v1';
```

### Сервис-слой (API-клиент)

```typescript
// api/client.ts — тонкая обёртка над fetch
async function apiRequest<T>(endpoint: string, options?: RequestInit): Promise<T> {
  const response = await fetch(`${API_BASE}${endpoint}`, {
    headers: { 'Content-Type': 'application/json', ...options?.headers },
    ...options,
  });
  if (!response.ok) {
    const error = await response.json().catch(() => ({}));
    throw new ApiError(response.status, error.detail || 'Unknown error');
  }
  return response.json();
}
```

### Все вызовы к API

| Функция | Endpoint | Когда вызывается |
|---------|----------|-----------------|
| `startQuiz()` | `POST /quiz/start` | При начале опроса |
| `submitAnswer(sessionId, questionId, answers)` | `POST /quiz/answer` | После выбора ответа |
| `getRecommendations(sessionId)` | `GET /recommendations/{sessionId}` | После завершения опроса |
| `selectProfession(sessionId, professionId)` | `POST /recommendations/select` | При выборе профессии |
| `getRoadmap(professionId)` | `GET /roadmap/{professionId}` | При открытии карты |
| `getRoadmapWithProgress(sessionId)` | `GET /roadmap/my/{sessionId}` | При открытии карты (если сессия есть) |
| `getProgress(sessionId)` | `GET /progress/{sessionId}` | Периодически / при загрузке карты |
| `markStepDone(sessionId, stepId)` | `PUT /progress/{sessionId}/step/{stepId}` | При клике на чекбокс |

### Обработка состояний в каждом запросе

```typescript
// Паттерн для каждого экрана:
const { data, error, loading } = useApi(getRecommendations, sessionId);

if (loading) return <Spinner />;
if (error) return <ErrorMessage message={error.message} onRetry={refetch} />;
if (!data) return <EmptyState message="Нет данных" />;
return <ResultsList recommendations={data} />;
```

## 13. Сборка и деплой

### package.json (ключевые скрипты)

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "preview": "vite preview",
    "test": "vitest",
    "lint": "eslint src/",
    "format": "prettier --write src/"
  }
}
```

### Переменные окружения (.env)

```
VITE_API_URL=http://localhost:8000/api/v1
```

### Деплой на Vercel (рекомендую)

1. `npm i -g vercel`
2. `vercel` — автодеплой из репозитория
3. В настройках проекта: Framework = Vite, Build = `vite build`, Output = `dist`
4. Добавить переменную `VITE_API_URL` = URL бэкенда

### Либо деплой на Netlify

1. Подключить GitHub-репозиторий
2. Build command: `npm run build`
3. Publish directory: `dist`
4. Environment variable: `VITE_API_URL`

## 14. Риски и их митигация

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| Не успеваем сверстать все экраны | Средняя | Высокое | Сначала делаем ядро: опросник → результаты → карта. Лендинг и анимации — в последнюю очередь |
| Бэкенд не готов к сроку | Средняя | Высокое | Используем моки (mock-данные) для разработки, подключаем реальный API когда появится |
| Сложности с адаптивом | Низкая | Среднее | Делаем mobile-first с самого начала |
| Не успеваем с тестами | Средняя | Низкое | Тесты только на ключевые сценарии: опросник, рендер карточек, клик по шагу |
| Кривой UX (пользователь теряет сессию) | Низкая | Среднее | sessionStorage сохраняет сессию, показываем понятные сообщения |
