### 🟢 1.2 Retry-логика в API-клиенте

**Где:** `frontend/src/api/client.ts`

**Почему:** При временных сетевых проблемах пользователь просто видит ошибку.

**Что сделать:**

```ts
async function apiRequest<T>(endpoint: string, options?: RequestInit, retries = 2): Promise<T> {
  for (let attempt = 0; attempt <= retries; attempt++) {
    try {
      const res = await fetch(...)
      if (!res.ok) throw ...
      return res.json()
    } catch (e) {
      if (attempt === retries) throw e
      await new Promise(r => setTimeout(r, 1000 * (attempt + 1)))
    }
  }
}
```

**Сложность:** ⭐ — 10 строк кода, сразу меньше багов.

### 🟡 2.5 Подтверждение выхода с квиза

**Где:** QuizPage — `beforeunload` + навигация

**Почему:** Если пользователь случайно нажал «назад» или закрыл вкладку, он потеряет всё (in-memory же). Предупреждение хотя бы сохранит данные.

**Что сделать:**

```tsx
useEffect(() => {
  const handler = (e: BeforeUnloadEvent) => {
    if (Object.keys(state.answers).length > 0) {
      e.preventDefault();
    }
  };
  window.addEventListener('beforeunload', handler);
  return () => window.removeEventListener('beforeunload', handler);
}, [state.answers]);
```

**Сложность:** ⭐ — 10 строк.

## 3. Надёжность и техдолг

### 🟠 3.1 Логирование (structured logging)

**Где:** Backend — добавить `structlog` или хотя бы `logging` с request-id

**Почему:** Сейчас логи SQLAlchemy — единственный источник информации. Невозможно отлаживать проблемы пользователей.

**Что сделать:**
- Middleware, которая добавляет `request_id` в каждый запрос
- Логировать каждый API-вызов: метод, path, status, duration
- Логировать ошибки с traceback

```python
@app.middleware("http")
async def log_requests(request: Request, call_next):
    start = time.time()
    response = await call_next(request)
    duration = time.time() - start
    logger.info(f"{request.method} {request.url.path} -> {response.status_code} ({duration:.2f}s)")
    return response
```

**Сложность:** ⭐⭐ — вечер.

### 🔵 4.1 Экспорт roadmap в PDF

**Где:** Frontend (RoadmapPage) + библиотека

**Почему:** Пользователь хочет распечатать план или сохранить его для офлайн-доступа. Killer-feature для кейса.

**Что сделать:** Использовать `html2canvas` + `jspdf` (или `print-js`):

```tsx
import { jsPDF } from 'jspdf';
import html2canvas from 'html2canvas';

const exportPDF = async () => {
  const el = document.getElementById('roadmap-content');
  const canvas = await html2canvas(el);
  const imgData = canvas.toDataURL('image/png');
  const pdf = new jsPDF('p', 'mm', 'a4');
  pdf.addImage(imgData, 'PNG', 0, 0);
  pdf.save('roadmap.pdf');
};
```

**Сложность:** ⭐⭐ — день, выглядит как «мы серьёзно подошли».

### 🟣 5.3 Docker multi-stage build для фронта

**Где:** `frontend/Dockerfile` (пока нет)

**Почему:** Сейчас фронт собирается вручную. Для продакшена хорошо бы собирать статику в Docker и сервить через nginx.

**Что сделать:**
- Stage 1: `node:20-alpine` → `npm ci && npm run build`
- Stage 2: `nginx:alpine` → скопировать `dist/` в `/usr/share/nginx/html`

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
```

**Сложность:** ⭐⭐ — час.

## 6. Архитектурные улучшения

### 🔴 6.1 TanStack Query (React Query) вместо useApi

**Где:** Frontend — `hooks/useApi.ts` → удалить, заменить на `@tanstack/react-query`

**Почему:** Текущий `useApi` не умеет:
- Автоматический рефетч (stale-while-revalidate)
- Кеширование
- Дедупликацию запросов
- Retry
- Инвалидацию кеша (например, после toggle шага — перезапросить прогресс)

TanStack Query даёт всё это из коробки.

**Что сделать:**
1. `npm install @tanstack/react-query`
2. Обернуть App в `<QueryClientProvider>`
3. Переписать `useApi` вызовы на `useQuery` + `useMutation`

```tsx
// Было
const { data, loading, error } = useApi(() => getRoadmap(id), [id]);

// Стало
const { data, isLoading, error } = useQuery({
  queryKey: ['roadmap', id],
  queryFn: () => getRoadmap(id),
});
```

**Сложность:** ⭐⭐⭐ — 1–2 дня на замену + рефакторинг.
