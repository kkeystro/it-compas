## 1. Описание продукта и бизнес-логика

### Концепция

«Карьерный компас» — это веб-приложение, которое помогает студенту без опыта в IT определиться с профессией и получить конкретный план действий на 12 месяцев.

### Проблема (боль пользователя)

Студент хочет войти в IT, но:
- не знает, какие профессии существуют;
- не понимает, какая профессия ему подходит;
- не знает, с чего начать обучение;
- теряется в огромном количестве курсов, книг и ресурсов;
- не видит конкретной дорожной карты с дедлайнами.

### Решение

Приложение проводит пользователя через 3 этапа:

1. **Опросник** — студент отвечает на 8–10 вопросов о своих навыках, интересах, предпочтениях и целях.
2. **Рекомендация** — система на основе ответов подбирает 3 наиболее подходящие IT-профессии с пояснением.
3. **Дорожная карта** — для выбранной профессии строится план на 12 месяцев: что учить, в каком порядке, какие проекты делать, где участвовать в хакатонах, куда отправлять резюме.

Пользователь может отслеживать свой прогресс, отмечая пройденные шаги.

## 3. Функциональные требования к бэкенду

### Модуль опросника
- Хранить вопросы с вариантами ответов.
- Каждый вариант ответа имеет веса для разных профессий.
- Поддерживать разные типы вопросов: single choice, multiple choice, шкала (1–5).
- Сессия опроса: пользователь может пройти опрос за один заход (без сохранения промежуточных ответов — для MVP).

### Модуль рекомендаций (Scoring Engine)
- После завершения опроса подсчитать взвешенную сумму баллов для каждой профессии.
- Учесть «рыночный коэффициент» востребованности профессии.
- Вернуть топ-3 профессии с скоринговым пояснением: **«Тебе подходит Frontend-разработчик, потому что ты указал интерес к визуальной части и начальные знания HTML/CSS»**.

### Модуль дорожных карт
- Для каждой профессии хранить структурированную карту:
  - Этапы (по месяцам или кварталам).
  - Внутри этапа: темы для изучения, ссылки на ресурсы, практические задания, хакатоны, компании для стажировки.
- Карта рассчитана на 12 месяцев (4 квартала).

### Модуль прогресса
- Пользователь может отметить шаг дорожной карты как «пройденный».
- Система возвращает процент выполнения всей карты.
- Отображать рекомендацию следующего шага.

| Метод | Endpoint | Описание | Request | Response |

## 6. Бизнес-логика рекомендаций (Scoring Engine)

### Принцип работы

1. Каждый вопрос опросника имеет набор взвешенных вариантов ответов.
2. Каждый вариант ответа связан с профессией и имеет **вес влияния** (от 0 до 10).
3. После прохождения всех вопросов считается **сумма баллов** для каждой профессии.
4. К сумме применяется **коэффициент рыночной востребованности** (1.0 — средняя, 1.2 — высокая, 0.8 — низкая).
5. Топ-3 профессии с наивысшим итоговым скором возвращаются пользователю.

### Формула

```
Score(profession) = Σ(weight_option * user_selected) * market_coefficient
```

Где:
- `weight_option` — вес варианта ответа для профессии (0–10)
- `user_selected` — 1 если выбран, 0 если нет
- `market_coefficient` — коэффициент востребованности (0.8–1.2)

### Пример данных для опросника

**Вопрос:** «Что тебе больше нравится делать?»
- «Рисовать макеты, продумывать интерфейсы» → Frontend: +8, UX/UI: +10, Backend: +1
- «Разбираться с базами данных и серверами» → Backend: +10, DevOps: +6, Frontend: +1
- «Анализировать данные и строить графики» → Data Science: +10, Analytics: +9
- «Настраивать инфраструктуру и автоматизировать» → DevOps: +10, Backend: +4

### База профессий для MVP

| Профессия | Коэффициент рынка |
|-----------|-------------------|
| Frontend-разработчик | 1.2 |
| Backend-разработчик | 1.2 |
| Data Science / ML-инженер | 1.1 |
| DevOps-инженер | 1.1 |
| UX/UI-дизайнер | 1.0 |
| Product Manager | 1.0 |
| QA / Тестировщик | 0.9 |
| Системный аналитик | 1.0 |

## 8. Модуль прогресса пользователя

### Как работает

1. При выборе профессии создаётся сессия пользователя (в БД).
2. В таблице `user_progress` фиксируется состояние каждого шага (пройден / не пройден).
3. `GET /progress` возвращает:
   - общий процент выполнения (пройденные шаги / всего шагов × 100);
   - список пройденных шагов;
   - следующий шаг (рекомендация);
   - прогресс по этапам.

### Визуализация (данные для фронтенда)

```json
{
  "overall_progress": 23.5,
  "stages_progress": [
    { "stage_id": 1, "title": "Основы", "progress": 50.0, "steps_total": 4, "steps_done": 2 },
```

## 12. Развёртывание и деплой

### Docker-образ

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app/ app/
COPY alembic/ alembic/
COPY alembic.ini .

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### docker-compose.yml

```yaml
version: "3.9"
services:
  backend:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=sqlite:///./app.db
    volumes:
      - ./app.db:/app/app.db
```

### Переменные окружения (.env)

```
APP_NAME=CareerCompass
API_V1_PREFIX=/api/v1
DATABASE_URL=sqlite+aiosqlite:///./app.db
DEBUG=true
```

## 13. Риски и их митигация

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| Не успеваем написать бэкенд | Средняя | Высокое | Делаем MVP: убираем аутентификацию, используем SQLite, фокусируемся на ключевом флоу |
| API не успевает к фронтенду | Средняя | Высокое | Синхронизируемся ежедневно, отдаём статический JSON-заглушки фронту пока пишем |
| Контент дорожных карт нереалистичен | Низкая | Среднее | Используем ChatGPT для генерации + проверяем руками |
| Проблемы с деплоем | Низкая | Среднее | Делаем Docker рано (21–22 мая), оставляем время на отладку |
| Менторы забракуют архитектуру | Низкая | Среднее | На первой менторской (19 мая) показываем архитектуру и получаем OK |

## 14. Чек-лист приёмки (для тестировщика)

### Функциональное тестирование

- [ ] `GET /health` возвращает `200 OK`
- [ ] `POST /quiz/start` возвращает первый вопрос с вариантами
- [ ] `POST /quiz/answer` с корректными данными возвращает следующий вопрос
- [ ] `POST /quiz/answer` с некорректными данными возвращает `422` или `400`
- [ ] `POST /quiz/finish` возвращает топ-3 рекомендации
- [ ] `GET /recommendations/{session_id}` возвращает те же рекомендации
- [ ] `POST /recommendations/select` сохраняет выбор профессии
- [ ] `GET /roadmap/{profession_id}` возвращает корректную структуру
- [ ] `GET /roadmap/my/{session_id}` возвращает карту с прогрессом
- [ ] `PUT /progress/{session_id}/step/{step_id}` отмечает шаг
- [ ] `GET /progress/{session_id}` показывает обновлённый процент

### Проверка данных

- [ ] Seed-данные загружаются без ошибок
- [ ] Вопросы опросника имеют все типы (single, multiple, scale)
- [ ] Дорожные карты содержат минимум 4 этапа на 12 месяцев
- [ ] Рекомендации имеют пояснение (причина выбора)

### Безопасность и стабильность

- [ ] API не падает при невалидном session_id
- [ ] CORS настроен для домена фронтенда
- [ ] Ответы API имеют понятную структуру (не сырая ошибка SQL)

### Интеграция

- [ ] Swagger-документация доступна по `/docs`
- [ ] API соответствует спецификации, переданной фронтенду
